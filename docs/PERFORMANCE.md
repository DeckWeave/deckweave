# Первые измерения нового приложения

Дата: 2026-11-01. Оптимизированные Windows release-сборки первого среза. Первые две строки — до аппаратного provider, третья — после подключения N4; во всех пробах без внешних плагинов и HTML backend. Это baseline, не подтверждение приемлемой нагрузки полноценного v1.

| Сценарий | Процессы | Private commit | Сумма working sets | CPU time / длительность |
|---|---:|---:|---:|---:|
| Реестр и один редактор виртуального устройства | 8 | 236,3 МиБ | 469,0 МиБ | 0,0938 с / 2,003 с |
| После закрытия редактора, только реестр | 7 | 248,6 МиБ | 418,4 МиБ | 0,1094 с / 2,002 с |
| Реестр и редактор подключённого N4, первый hardware slice | 8 | 240,9 МиБ | 474,5 МиБ | 0,2969 с / 5,004 с |

Измерялось дерево выбранного release executable и его WebView2-потомков. Чужие WebView-приложения не включались. Private commit не равен физической RAM, сумма working sets может повторно учитывать shared pages. CPU time — сумма времени процессов, не процент загрузки всего компьютера.

Закрытие редактора уменьшило число процессов на один, но в этой короткой последовательности private commit не уменьшился. Поэтому нельзя утверждать, что вся память окна сразу возвращается системе, или делать вывод об утечке по двум точкам. Нужны повторные циклы и длительное наблюдение после появления реальных backend. Численный бюджет владелец не задавал; ресурсная цель остаётся открытой инженерной задачей.

Старые измерения HTML-часов относятся к другому host и другой нагрузке; напрямую сравнивать их с этими двумя окнами как «процент улучшения» нельзя. В первом срезе нет interval polling, активных внешних плагинов и постоянного перерисовывания счётчика; оптимизация работы при закрытых редакторах и tray входит в следующий этап.

Аппаратная строка добавлена после подключения реального N4: HID worker читает ввод с timeout, supervisor перечисляет устройства раз в 2 секунды, CONNECT heartbeat — раз в 8 секунд. UI по-прежнему обновляется по событиям; параллельные refresh IPC объединяются. В пробе счётчики ввода оставались нулевыми, OUT = 10, новые кадры в простое не накапливались. Это короткая проверка отсутствия постоянной перерисовки, не проверка длительной работы или расхода при быстрых вращениях/внешних плагинах. Разницу с предыдущей сборкой нельзя полностью приписать драйверу по одному измерению.
