# Уточнение редактора и изображений

Дата 2026-11-02. Основание: [принятая аппаратная проверка](ACCEPTANCE-NEXT.md) и замечания владельца к интерфейсу.

**Последующее исправление:** владелец сообщил о чёрном физическом дисплее после этой сборки. JPEG 4:4:4/optimized Huffman отменён; ограничение shared dials пересмотрено. Текущий результат и настройка папок/крутилки — [в исправлении навигации и вывода](NAVIGATION-AND-DISPLAY-FIX.md). Ниже сохранён ход первой итерации и её программные наблюдения.

## Поведение

Действие из библиотеки перетаскивается на конкретный key, dial или touch region. Выбор заранее не требуется. Совместимый получатель подсвечивается; несовместимый controller не назначается. Drop выбирает получателя и сохраняет назначение через тот же Core command, что и нажатие в библиотеке. Выполнение остаётся отдельной командой «Проверить». Внешние файлы/текст не интерпретируются как действия.

Внутренний перенос использует pointer capture и порог движения 6 px, показывает подпись у указателя и не зависит от передачи DataTransfer операционной системой. Drop вне совместимого элемента отменяет перенос; Escape также отменяет его. Click после drop подавляется, чтобы не назначить действие повторно.

Обычные страницы нумеруются подряд, папки сохраняют собственные имена и вход через назначенную кнопку. Существующие цифровые названия отображаются по порядку корневых страниц; ID, содержимое и ссылки переходов сохраняются. Создание следующей страницы считает только корневые страницы.

Высота настроек и ширина библиотеки меняются перетаскиванием границ и клавишами стрелок на границе (Home/End — пределы). Размеры сохраняются локально и ограничиваются размерами окна. Это изменение областей редактора, не произвольное перемещение физических органов управления. Настройки расположены адаптивной сеткой, заголовок показывает имя действия. Изображение feedback остаётся на полосе; круглая крутилка показывает номер и маркер.

Технический JSON и перезапуск плагина находятся в «Дополнительно». Поле проверки touch жестов раскрывается отдельно. Кнопка оригинального PI показывается только при наличии PI. Область с несколькими связанными крутилками принимает native Panel widget; несовместимые действия на неё не назначаются. Panel-плагин также можно перенести на связанную крутилку: назначение сохраняется в общей области.

Ряд кнопок занимает X=32…576. Полоса теперь имеет те же границы, 544×87,04 при native raster 800×128. Убран прежний выступ шириной 12. Геометрия touch и hit testing использует те же границы.

Наш Panel Slider также адаптируется к реальному canvas: при 200×128 получает собственный viewBox и переносит служебную подпись под значение. Полноразмерная раскладка 800×128 больше не втискивается в отдельный слот. Изменение проверено через настоящий Node backend и native preview.

## Изображения и пределы улучшения

Плагин OnAirClock рисует canvas 144×144. В установленном app.js: центр 72, радиус внешних точек 0,8×83=66,4, толщина 2,2. Поэтому источник сам оставляет около 3,4 пикселя с каждой стороны (примерно 2,6 после преобразования в 112×112). Дата имеет 16–18 px Verdana и цвет dotColor, по умолчанию #ab0000. После уменьшения это около 12,4–14 px. Файлы установленного плагина не изменялись.

В DeckWeave изображение занимает весь raster 112×112, дополнительный программный отступ не добавляется. Удалять исходный отступ автоматическим crop нельзя без изменения композиции/возможного обрезания других плагинов. Физический bezel/масштабирование firmware этим расчётом не измерены. Увеличить только дату внутри готового bitmap универсальный host не может; цвет настраивается в оригинальном PI.

Передача улучшена: Lanczos3 вместо Triangle при преобразовании raster, JPEG 4:4:4 вместо стандартного 4:2:0, качество начинается с 95, оптимизированные таблицы Huffman. Сохраняются лимиты 10 KiB для key и 128 KiB для strip; качество снижается только при превышении. SVG сразу растеризуется в нужный размер. Preview физического N4 использует тот же отправленный JPEG, развёрнутый обратно на 180°.

Регрессии проверяются тестами: папка не расходует номер страницы и сохраняется после restart; совпадение границ и aspect полосы; одноцветный штрих толщиной 1 px после JPEG без цветового расплывания на соседа; сложное изображение укладывается в транспортный лимит. Итоговая оценка читаемости на физическом LCD остаётся визуальной, её нельзя доказать screenshot приложения.
