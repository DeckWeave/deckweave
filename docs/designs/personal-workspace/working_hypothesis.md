# Personal daily workspace: working hypothesis

Date: 2026-11-03. The owner delegated selection of initial commands and allowed
inspection/change of personal settings, asking to improve the result through use.
This supersedes further workflow clarification and readiness prompts for this run.

Configure a new Mirabox profile, preserving existing profiles and keyboard firmware
assignments. Use Home, Reports, Codex, Browser and System pages. Home opens/focuses
VS Code, Codex, the default browser, Telegram, Telemost and Zotero and links to task
pages. Reports uses the installed Typewriter/Tinymist commands for preview, PDF
export, formatting, figure/table/formula/reference insertion and outline. Codex
provides useful supported navigation/context controls without sending a prompt,
starting an agent job, approving a command or publishing user content. Browser
provides navigation/tab/search/zoom controls without submitting forms or messages.
Treat desktop Codex and its VS Code extension as distinct command targets.

Keep weather for the Mirabox's existing selected city, a large digital date/time,
and Pomodoro on fixed touch-strip regions on every new page. A full Pomodoro has
work/short-break/long-break state, pause/resume/reset/skip and once-per-transition
host sound. It continues across pages/profiles; restart does not replay old sounds
or start a cascade of missed breaks. Default to 25/5/15 minutes, four work rounds,
and manual start of the next phase, with editable settings. Reuse the host job
authority; do not run independent plugin and host clocks for the same run.

System page shows CPU, used RAM, busiest GPU-engine load and dedicated GPU-memory
use, with adapter and unavailable states defined. Share native sampling, bound
its rate, and avoid starting an external tool for every sample. No telemetry is
sent to a server. Weather retains explicit location selection; Elgato Weather stays
disabled. Prefer information on the hardware, not new desktop overlay windows.

Preserve original Mirabox JPEG output. Render for actual key/strip dimensions,
prioritizing one large value and short labels. Avoid tiny footer instructions and
unnecessary analog dial detail. Keep familiar neutral colors with a restrained
warm accent and strong text contrast. Do not claim physical readability from a
large application screenshot alone.

App controls must address the intended application/window or report inability;
never inject a command into whichever unrelated app happens to be focused.
Inspect installed application paths and registered editor commands instead of
asking the owner to supply paths. If a companion integration is needed, ship its
source and local installation instructions and test an isolated fixture first.
Snapshot personal configuration before applying changes, reject stale revisions,
make the setup repeatable without duplicating profiles, and never overwrite the
owner's unrelated VS Code settings or device assignments.

Defer key-note previews, Telegram notification previews and unread email to the
next stage. They require separate source/identity/privacy decisions. No private
chat/email content is read or transmitted during this setup.
