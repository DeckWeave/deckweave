# Ближайшее продолжение

Дата 2026-11-01. Три согласованных направления доведены до следующего сквозного среза: фон/tray; настоящий Elgato backend/PI; навигация и составные действия. Дополнительно подключены native panel regions/widgets и совместное управление с крутилками. [Текущее состояние](STATUS.md), [доказательства](RUNTIME-PROGRESS.md).

## Следующий необходимый ввод владельца

Только оставшаяся физическая неопределённость: D2–D4, USB reconnect, новая маршрутизация pointer Y/drag/swipe. [Конкретная приёмка](ACCEPTANCE-NEXT.md) должна описывать подготовленную раскладку и ожидаемый результат. Проверенные ранее K1–K10, ориентация, крайние исходные touch области и D1 не повторяются ради галочки.

## Работа после приёмки

1. Исправить реальные несовпадения capture/hit testing/display, если они обнаружатся. Разделять firmware click, реальные down/up и отсутствие точного Y.
2. Довести привычный редактор: управление/переименование/удаление профилей, страниц и папок, более удобный compositor, отображение сложных сценариев и состояния selected actions. Существующие Engine/Core semantics сохраняются.
3. Стабилизировать provider registry на втором физическом adapter, вынести built-in geometry/capabilities из Core; затем выпускать внешний process SDK/templates. [Граница](PROVIDER-CONTRACT.md) уже зафиксирована, прототип N4 не объявляется готовым публичным SDK.
4. Расширять совместимость по конкретным необходимым пакетам и подтверждённым пробелам [матрицы](PLUGIN-COMPATIBILITY.md); не тратить время на каждую малую деталь каталога до появления потребности.
5. Runtime distribution/installer, длительные проверки отказов и всего дерева процессов, release-замеры, затем macOS/Linux. Текущий короткий debug замер не является бюджетом производительности.

Повторное согласование стека, режима Smart Profiles, панели, уровня OpenDeck и лицензии не требуется. Технические решения уже делегированы; новые вопросы владельцу нужны только при существенной развилке взаимодействия.
