# Что делать после первого коммита

Дата: 2026-11-01. Зафиксирована первая работающая основа, а не полноценный выпуск. Стек и продуктовые требования уже приняты; повторных вопросов о них не требуется. [Статус](STATUS.md), [полный план](PLAN.md), [решения владельца](DECISIONS.md).

## Следующий результат — устройство работает при закрытом редакторе

Приоритет 1, продолжение фазы 3. Core, persistent instance identity, worker N4 и input/output уже работают. Владелец подтвердил исправленные кнопки, крайние touch области и D1; пропорции preview исправлены. Сейчас закрытие всех окон завершает приложение, а полноценного внешнего provider SDK ещё нет.

Задачи:

- [ ] Tray, открытие реестра из tray, явная команда выхода и корректная остановка workers ([desktop](../modules/desktop.md)). Закрытие редактора снимает editing pause и оставляет обычные действия работающими.
- [ ] Проверить reconnect и ожидаемые статусы: отключённое устройство — Offline, отказ открытия — Error; старое поколение не исполняет ввод и не публикует кадры. После reconnect текущая страница рисуется заново без повторения действий ([providers](../modules/providers.md), [runtime](../modules/runtime.md)).
- [ ] Описать минимальные descriptor/capabilities/input/present/lifecycle provider contracts на основе виртуального и N4 instances, отделить модель N4 от Core там, где она ещё зашита. Один provider продолжает обслуживать независимые instances ([providers](../modules/providers.md)). Публичный SDK стабилизировать после второго adapter, а не объявлять внутренний N4 worker внешним плагином.
- [ ] Завершить аппаратную приёмку D2–D4, USB disconnect/reconnect и отмены touch movement; сохранить raw evidence и результаты ([приёмка](N4-ACCEPTANCE.md), [panels](../modules/panels.md)).

Готовность: закрытие всех окон оставляет работающий runtime в tray; повторный запуск поднимает существующий процесс; явный выход освобождает USB; reconnect сохраняет instance/назначения/страницу и убирает зависшие pressed; один отказ не останавливает другие instances. Отсутствие нескольких физических устройств компенсируется lifecycle-тестами, но не выдаётся за аппаратную приёмку нескольких N4.

Вмешательство владельца нужно только для физических действий: переподключить USB, проверить оставшиеся крутилки и наблюдать результат. Технические решения и реализация этой части уже делегированы.

## Следом — одно настоящее действие Elgato от настройки до устройства

Приоритет 2, первые срезы фазы 4. Цель — проверяемая совместимость конкретного пакета, не видимость поддержки всего каталога. Опора: [исследование совместимости](research/2026-11-01/COMPATIBILITY.md), [actions](../modules/actions.md).

- [ ] Сначала manifest scanner, запуск одного native/Node backend, WebSocket registration, устойчивые contexts, willAppear/willDisappear, down/up и setTitle/setState/setImage ([actions](../modules/actions.md)).
- [ ] Затем настройки действия, сохранение/restart, настоящий Property Inspector и его связь с backend. Добавить HTML backend и отдельно измерить процессы, пока редактор закрыт ([desktop](../modules/desktop.md), [actions](../modules/actions.md)).
- [ ] Проверить известный диагностический пакет и полезный установленный плагин на N4; падение backend показать в UI с сохранением назначения. OBS подключать через подходящий проверенный artifact либо obs-websocket adapter, не по результату регистрации старого архива ([actions](../modules/actions.md)).

Готовность: действие назначается в редакторе, настраивается в PI, запускается физической кнопкой, обновляет её изображение и сохраняет настройки после restart; закрытый PI не останавливает backend. Защищённые/неподдержанные пакеты получают понятный статус.

## Дальнейшая последовательность

1. Профили, папки, кнопочная навигация и pinned; системные действия запуска программ/клавиатурных команд в привычном редакторе.
2. Multi Action/Delay/Switch и Key Logic: single/double/hold, отмена и видимая смена самой кнопки; затем настоящий Smart Profiles monitor с уже принятой глобальной editing pause.
3. Полноценные native panel layouts/widgets, совместимые actions в областях, настраиваемые dial associations, Dial Stack и Action Wheel. Текущие пять touch-областей и индикаторы — проверочная раскладка, не конечный редактор.
4. Длительная работа, измерения всего дерева процессов, packaging и Windows release. IO84/MX4/Android и синхронные группы остаются отложенными по решениям владельца.

Подробные задачи и критерии — в фазах 5–7 [PLAN](PLAN.md). Эти приоритеты уточняют порядок работы и не исключают обязательные функции первого полноценного выпуска.
