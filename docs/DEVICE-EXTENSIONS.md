# Расширения и настройки устройств

Срез 2026-11-02. Действия, поддержка оборудования и подключённые экземпляры управляются отдельно. Обычный запуск открывает редактор последнего устройства. Общее управление находится в **Настройки → Плагины / Устройства**.

## Удаление действий и пакетов

В **Плагины → Установленные** доступны поиск и фильтр «Действия / Поддержка устройств». Пакет из каталога данных можно удалить; пакет из рабочего репозитория или Elgato можно отключить от DeckWeave. Внешние исходники и установленный Stream Deck при этом не удаляются.

Перед подтверждением показаны затронутые назначения, в том числе вложенные сценарии, папки, закреплённые действия и неактивные профили. Профили, назначения и настройки остаются в базе; недоступный пакет можно установить или подключить снова. Удаление останавливает backend, его дочерние процессы и окна настроек. Ошибка завершения оставляет состояние для повторной попытки, а сохранённый запрет запуска действует после перезапуска приложения.

Чтобы убрать одно назначение, используйте удаление действия в редакторе выбранной кнопки/крутилки или шага сценария. Удалять весь пакет для этого не требуется.

## Экземпляры оборудования

**Настройки → Устройства** содержит активные устройства, «Сохранённые / удалённые» и «Обнаруженное оборудование».

- **Убрать из DeckWeave…** останавливает экземпляр, закрывает его редактор и сохраняет профили. Повторное обнаружение не возвращает его самовольно.
- **Восстановить устройство** возвращает сохранённый экземпляр с прежними ID и назначениями. До подключения он остаётся вне сети.
- **Забыть сохранённые настройки…** — отдельное окончательное действие. Само по себе оно не разрешает автоматическое возвращение оборудования.
- Поддержка устанавливается один раз на provider, затем обслуживает несколько независимых экземпляров. Для нового внешнего оборудования нужен явный выбор в «Обнаруженное оборудование».

Если драйвер не имеет постоянной аппаратной identity, после его перезапуска выберите обнаруженное устройство и явно сопоставьте с сохранённым экземпляром. Совпадение модели не считается достаточным основанием для автоматического сопоставления. Сохраняются имя, профили и назначения; старые удержания и незавершённые действия отменяются.

## Mirabox N4 Pro

В редакторе откройте **Настройки устройства**: вибрация при нажатии, яркость экранов, яркость подсветки крутилок. Те же параметры доступны из общих настроек устройства. Открытие настроек ничего не записывает; меняется только явно выбранное поле. Значение сохраняется и отправляется рабочему HID-потоку.

У устройства нет подтверждённого чтения этих значений обратно. Поэтому «отправлено» означает успешную передачу команды, а видимый результат проверяется на устройстве. Проверенный формат JPEG 4:2:0 сохранён.

## IO Type 84 и подсветка всей клавиатуры

Локальный адаптер находится рядом с приложением в `device-io-type-84`. Пакет `dist/dev.deckweave.io-type-84-0.1.0.deckweave-device.zip` устанавливается через **Плагины → Установить из файла…**, затем устройство добавляется через «Обнаруженное оборудование». Поддерживается точно проверенная модель Magnetic White с прошивкой 1.17.

У клавиатуры нет фиктивных экранов на клавишах. Полноразмерная вкладка подсветки управляет штатной композицией всего устройства: режим, яркость, скорость, направление, цвета. Индивидуальный цвет доступен только для подтверждённых адресов: первое физическое чтение подтвердило один адрес, поэтому поддержка цветов всех 84 клавиш не заявляется. Соответствующий штатный режим выбирается явно. Именованные пресеты можно привязать к профилю или действию. Ручное редактирование блокирует конкурирующие автоматические изменения до выхода; отклонённые запросы не проигрываются позже.

Настройки клавиатуры отдельно показывают Main/Fn и параметры срабатывания/RT выбранных клавиш. Запись ограничена обычными keyboard usages и проверенными полями, сохраняет остальные байты и подтверждается чтением обратно. Добавлено отдельное наблюдение глубины с круговыми индикаторами: [управление и точные границы](IO84-EDITOR.md). Цифровые события клавиатуры, захват ввода и потоковые композиции пока не заявлены. Нормальный ввод не перехватывается.

Перед записью адаптер сохраняет исходный снимок затрагиваемых блоков вне пакета. Неопределённый результат блокирует дальнейшую запись. Восстановление требует свежего просмотра различий и явного подтверждения текущего экземпляра; доступ к нему сохраняется даже после прерванного удаления и перезапуска. Это не полный backup прошивки и не автоматический reset. Временные onboard-эффекты пока не доступны.

## Создание собственного расширения

Новая репозитория не требуется для локальной разработки. Три существующих проекта обслуживают оба вида расширений:

| Проект | Назначение |
| --- | --- |
| `plugin-sdk` | Action runtime и предварительный device protocol/types/validators |
| `plugin-template` | Отдельные генераторы действий и поддержки устройств; автономные тесты и упаковка |
| `plugin-registry` | Типизированные записи action/device, проверка локального workspace и будущих release archives |

Из каталога `plugin-template`:

```powershell
node bin/create.mjs --device ../my-device dev.example.mydevice "My device"
cd ../my-device
npm test
npm run validate
npm run pack
```

Шаблон включает собственную копию SDK. Его mock моделирует два независимых устройства без USB. Для реального оборудования автор реализует discovery, descriptor, транспорт, чтение/запись и завершение. Настройки/геометрия объявляются драйвером, интерфейсом и исполнением действий владеет DeckWeave. [Границы текущего host](PROVIDER-CONTRACT.md).

Контракт предварительный: внешние LCD/touch ещё не имеют полного паритета со встроенным N4. Новые API не следует объявлять стабильными до проверки вторым физическим адаптером. Реестр пока использует локальные development entries; публичные ссылки релизов не выдуманы. IO содержит заимствования из прототипа без установленной лицензии на публичное распространение и пока остаётся локальным.

Для текущей локальной сборки IO уже подключён как development support из игнорируемого `deckweave/device-plugins`; это собранная копия соседнего проекта, не исходники в основном Git. Повторная сборка нового драйвера требует обновления этой копии либо установки нового ZIP. Runtime state и recovery snapshots хранятся отдельно от этой папки.

## Проверки реализации

`npm run check` проверяет UI/format/build, Clippy, Rust/JS и ссылки документации. Дополнительный regression с реальным соседним SDK: `cargo test -p deckweave-desktop device_providers::tests::real_sdk_close --locked -- --ignored`.

Для изолированной native-проверки закройте другие экземпляры DeckWeave, соберите debug, задайте `DECKWEAVE_SMOKE_DEVICE_ARCHIVE` путём к mock ZIP и выполните `node scripts/smoke-installer.mjs`. Физическое оборудование в этом тесте отключено. [Последний результат](evidence/2026-11-02/device-extension-lifecycle-smoke.json), [первое физическое чтение IO](evidence/2026-11-02/io-type-84-read-only.json).

## Приёмка на оборудовании

Программные проверки удаления, сохранения, повторной установки, двух instances, отказов процессов, сопоставления и восстановления выполняются автоматически. Уже принятые кнопки, крутилки и сенсорный ввод Mirabox повторять не нужно.

1. **Mirabox:** в настройках устройства измените яркость экранов, затем отдельно подсветку крутилок — меняется соответствующая часть. Выключите/включите вибрацию и нажмите физическую кнопку. Именно видимый эффект и вибрацию нельзя доказать программным ACK.
2. **IO Type 84:** после подключения проверьте обычную печать; затем один штатный режим, яркость и цвет подтверждённой клавиши в режиме своих цветов. Проверьте, что остальные клавиши сохраняют настройку. Отдельно выключите и включите питание, чтобы установить фактическую стойкость onboard-настроек.

Не нужно намеренно обрывать запись на реальной клавиатуре: аварийные пути и cold recovery проверяются на изолированном provider. Для переназначения/RT сначала достаточно одной заведомо некритичной клавиши и возврата исходного значения; массовую перенастройку до этой проверки не выполнять.
