# Оригинальный Elgato Weather

DeckWeave распознаёт установленный **Elgato Weather 1.2.1.103** и использует его оригинальные Node backend, Property Inspector и изображения. Пакет не включён в репозиторий: он должен оставаться установленным через Elgato. Нужен доступный `node`.

В полном каталоге Plugins доступны сведения о Weather, Forecast и Air Quality для кнопок и крутилок. По умолчанию backend и его PI заблокированы до отдельного разрешения определения местоположения по внешнему IP, действия скрыты из Keys/Dials. После разрешения можно перетащить действие на нужный элемент, открыть настройки плагина, выбрать город и единицы измерения. Это оригинальный PI; его настройки сохраняет host DeckWeave. Действия нажатия и вращения реализует исходный backend.

## Разрешение сетевого определения местоположения

Оригинальный backend при старте запрашивает `https://api.ipify.org?format=json`, затем передаёт полученный IP по очереди сервисам `ip-api.com` (HTTP), `ipinfo.io` (HTTPS), `ipapi.co` (HTTPS), пока один не вернёт местоположение. Это происходит даже при вручную заданном городе и `autoSetUserLocation=false`. `showUserIpInLogs=false` скрывает IP в части журналов, но не отменяет передачу.

Штатный `offlineMode` останавливает и геолокацию, и получение погоды, поэтому не подходит как независимое отключение геолокации. Заполненный список `globalSettings.timestamps` может временно остановить запрос по дневному лимиту; подделывать этот журнал DeckWeave не будет.

Настройка `preferences.allow_weather_geolocation` по умолчанию `false`. До разрешения процесс не создаётся, PI не открывается, действие показывает объяснение. При отзыве разрешения host завершает сессию; после включения запускает её заново. Собственный DeckWeave Weather может использовать город/координаты без определения IP и не зависит от этого разрешения.

**Решение владельца от 2 ноября 2026:** оставить Elgato Weather выключенным и пользоваться собственной погодой DeckWeave. Текущее выбранное состояние — `allow_weather_geolocation=false`; согласие на сетевое определение IP не ожидается и не предполагается.

## Почему требуется отдельный дескриптор

У установленной версии защищён `manifest.json`, но `bin/plugin.js`, `ea/*/action.md`, `ea/*/settings-schema.json`, `en.json`, `ui/*.html` и `layouts/weather.json` читаемы. Независимый дескриптор в [catalog.rs](../apps/desktop/src-tauri/src/plugins/catalog.rs) задаёт только идентификаторы, имена, контроллеры и пути к уже установленным файлам. Защищённый manifest не расшифровывается и не заменяется; оригинальный SDK сам штатно обрабатывает его как недоступные метаданные.

Дескриптор применяется только к `com.elgato.weather` с заголовком `ELGATO` в manifest и точным SHA-256 читаемого backend:

```text
d4b0b6ec32dee0de0eb9ee0ef33e62f1ce9fa7bc32521b75c6941653be267827
```

Версия 1.2.1.103 указана в открытом changelog пакета. При изменении backend интеграция останавливается с понятной ошибкой до повторной проверки совместимости. Тестовое внутреннее действие `viewlayertest` не предлагается пользователю.

## Отдельные рабочие данные

Backend пишет относительно cwd, `APPDATA` и домашнего каталога. Поэтому host создаёт неизменённую рабочую копию статических файлов в `<DeckWeave data>/plugin-runtime/com.elgato.weather/1.2.1.103/home/AppData/Roaming/Elgato/StreamDeck/Plugins/com.elgato.weather.sdPlugin` и запускает её оттуда. `USERPROFILE`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `TEMP` и `TMP` у процесса указывают в эту область DeckWeave. Это разделение данных, не системная песочница стороннего исполняемого кода.

Существующие `logs` и `storage` Elgato не копируются. Данные нашей рабочей копии сохраняются между запусками. Копирование ограничено 16 MiB, отвергает ссылки и не изменяет оригинальный пакет. Сам backend и остальные сторонние ресурсы не публикуются в Git.

## Проверка и границы вывода

Изолированный процесс оригинального backend подтвердил регистрацию WebSocket, обработку `willAppear`, сообщения `setSettings` и `setImage`. Начальная проверка внутри sandbox получила отказ сети `EACCES`. Один последующий разрешённый сетевой запуск получил weather API cache для заданного Берлина и изображения длиной 5616 символов после начального splash 317 символов. Это проверяет получение данных и изображения от backend, но не качество финального отображения host.

Последующий углублённый сетевой probe был отклонён автоматической проверкой из-за автоматической передачи внешнего IP сервисам геолокации. Он не повторялся. Владелец выбрал оставить backend выключенным и использовать собственный плагин; дальнейшие сетевые испытания оригинала не запланированы. Одновременные Weather/Forecast/AQI/Encoder и смена вида по нажатию пока не приняты: предыдущий частичный probe подтвердил только lifecycle этих contexts. Сводка без стороннего кода и содержимого окружения: [weather compatibility evidence](evidence/2026-11-02/elgato-weather.json).

Unit tests проверяют отказ неизвестной версии без изменения защищённого manifest, состав дескриптора, побайтовое копирование ресурсов, разделение данных и явное разрешение перед запуском/PI. Поддержка собственных Panel widgets и original Elgato Keypad/Encoder различается: этот пакет предлагается как оригинальные Keypad/Encoder actions. Полная точность всех пользовательских layouts не заявляется; общие ограничения изложены в [PLUGIN-COMPATIBILITY.md](PLUGIN-COMPATIBILITY.md).

Статическое исследование исходного читаемого `bin/plugin.js` проведено REA (`ev_c9fa456b85697ac90152e59b33fd2eef2e37eafd9130e51873bafa52eda7994a`). Оно было частичным и само по себе не подтверждало запуск или работу API; для этого использован отдельный runtime probe. Физическое устройство не требуется для проверки регистрации, PI и получения изображения host, но этот probe не доказывает качество отображения на Mirabox.
