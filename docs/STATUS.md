# Текущее состояние DeckWeave

Обновлено: 2026-11-01. Архитектура подготовлена, начат новый код на Rust + Tauri 2 + Svelte. Владелец разрешил самостоятельно принимать технические решения и обращаться только при критической развилке интерфейса/поведения. Повторного согласования технических решений не требуется.

## Что работает

- Rust Core — единственный владелец конфигурации, активной страницы, ввода и feedback. Геометрия адресуется по instance.
- SQLite: транзакционная запись до публикации новой revision, восстановление после restart, отказ при повреждённой/неизвестной схеме без reset. Runtime pressed и демонстрационные значения не сохраняются как конфигурация.
- Реестр виртуальных устройств; добавление независимых instances; отдельное окно каждого устройства. Повторное открытие поднимает существующее окно.
- Страницы, назначение/удаление Counter и Toggle, название назначения без Apply. Выбор не исполняет действие.
- Отдельная команда «Проверить»: down → видимое нажатие → up → feedback; Toggle меняет вид самой кнопки. Для виртуального dial предусмотрена проверка вращения с signed ticks.
- Собственная сенсорная поверхность отделена от keys/dials; в первом срезе четыре фиксированных touch-контрола, которым можно назначать встроенные действия. Произвольный внешний panel plugin ещё не реализован.
- Глобальная editing session привязана к окнам настроек, закрытие последнего снимает паузу. Реального Smart Profiles foreground monitor пока нет.
- en/ru; desktop command scope не позволяет окну одного instance исполнять действия другого.
- Mirabox N4 Pro: встроенный transport crate, автообнаружение Windows, постоянная hardware identity, отдельный worker каждого instance, reconnect/generation, кнопки/dials/touch input adapter, 112×112 JPEG на 10 физических клавиш и BGPIC 800×128 на полосу. Preview показывает те же JPEG. Полоса использует тестовую раскладку T1–T5 с индикаторами D1–D4; внешний panel SDK ещё не реализован.
- Ограниченный журнал последних 256 raw/decoded входов и snapshot в app data `n4-diagnostics.json`. Статусы Connected/Offline/Error и счётчики ввода/передачи видны в UI. USB/JPEG/file I/O выполняются вне Core lock.

## Проверено

32 Rust-теста: 10 workflow/storage/input, 4 hardware session tests, 9 desktop/routing/output tests, 8 codec/transport/render tests и replay захвата владельца. Svelte check без ошибок/предупреждений, production web build, cargo fmt/clippy с запретом предупреждений, native release build. Release-сборка через npm run build запускается, прежние устройства/страницы сохранены. Единая команда проверки — npm run check.

В настоящем Windows-приложении: открыть устройство, выбрать кнопку без запуска, выполнить Counter, изменить название, закрыть/перезапустить и увидеть сохранённое название, добавить второй instance, назначить Toggle на пустую кнопку, выполнить и увидеть изменение кнопки, добавить страницу/вернуться, переключить ru/en. Найден и исправлен выход инспектора за нижнюю границу стандартного окна.

## Как продолжать

Ближайший конкретный результат и критерии готовности: [NEXT](NEXT.md). Первый коммит фиксирует работающий hardware slice; следующим идёт tray/lifecycle/reconnect, затем сквозной Elgato action/PI.

1. Читать [решения](DECISIONS.md), [архитектуру](ARCHITECTURE.md), [план](PLAN.md) и [UI](UI.md). Фазы 1–2 выполнены в указанном ограниченном объёме.
2. Текущий результат — hardware provider/N4 в работе, основная физическая проверка кнопок/полосы/D1 подтверждена. Продолжить tray/lifecycle, статусы и reconnect; оставшиеся аппаратные проверки перечислены в [N4-ACCEPTANCE](N4-ACCEPTANCE.md). Происхождение перенесённых частей сохранено в README драйвера; старый draft/apply UX не возвращать. Во время аппаратной проверки у HID должен быть один владелец.
3. Затем Elgato host/PI, полная навигация и составные действия, собственные панели/Dial Stack/Action Wheel по плану. Их нельзя считать готовыми по документации или сокращать объём v1 до первого среза.
4. Не спрашивать заново стек, Smart Profiles pause, Dial Stack/Action Wheel, гибкую сенсорную панель, импорт или доступность Elgato. Все ответы есть в DECISIONS.

## Ограничения первого среза

Сторонние Elgato-плагины, profiles/folders/pinned, Multi Action/Delay/Switch, Key Logic, Smart Profiles monitor, Dial Stack/Action Wheel и внешний panel plugin пока не реализованы. Работают только безопасные встроенные Counter/Toggle. Наличие кнопки Plugins показывает явное сообщение о будущем этапе, а не фиктивно установленный пакет. N4 output охватывает кнопки и тестовую полосу; полный compositor с произвольными plugin widgets и калибровка жестов остаются. Touch adapter пока single-contact в областях полной высоты, с отменой незавершённого контакта через 3 секунды. Несколько физических устройств одновременно не проверялись; публичный внешний provider SDK ещё не реализован.

Закрытие всех окон завершает процесс; tray/фоновая работа предусмотрены следующим этапом. Приложение использует отдельный identifier app.deckweave.studio и не мигрирует старые настройки. Публикация и push не выполнялись; первый локальный коммит фиксирует этот срез.

## Исследование

Сохраняется [исследовательский пакет](research/2026-11-01/README.md). Elgato-устройства нет; три видео недоступны для воспроизведения, просмотр не заявляется. Эти ограничения не блокируют разработку по доступным первичным источникам и собственным проверкам. Обнаруженные тонкости поведения отдельно отмечаются как непроверенные, а не выдаются за паритет.
