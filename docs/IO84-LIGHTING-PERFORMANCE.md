# Отзывчивость подсветки IO84

Дата: 2026-11-02. Исправление замечания владельца о задержке смены общего цвета и мигании кнопки чтения.

## Причины

Старая транзакция для одного параметра подсветки трижды читала полную модель: до записи, перед SET и после SET. Каждое полное чтение — 50 HID запросов, включая назначения Main/Fn, индивидуальные цвета и срабатывание. Вместе с SET и его readback получалось 152 обмена.

UI дополнительно блокировал палитру до проверки результата и узнавал о завершении периодическим опросом раз в секунду. Фоновый опрос устанавливал тот же `loading`, что и ручное чтение, поэтому кнопка меняла состояние каждую секунду. Синхронные IPC могли задерживать поток окна, ожидая сохранения Core и сериализации конфигурации.

## Изменение

- Для общего света — четыре обмена: GET сохранённого блока, GET проверки перед записью, SET, GET строгого readback. До SET сохраняются исходные 16 байт и durable intent. Снимок schema 3 явно ограничен подсветкой; свежесть остальных полей не заявляется. Восстановление читает актуальное устройство и меняет только записанные поля подсветки. Полные операции остаются для назначений, срабатывания и индивидуальной таблицы.
- Палитра не блокируется на период проверки предыдущего RGB. Завершённые жесты объединяются до последнего состояния, одновременно исполняется одна запись. Ошибка удаляет неотправленный хвост; открытие/повторное подключение не повторяет его.
- Узкий `device_provider_session` возвращает статус одного экземпляра. Фоновый опрос не показывает spinner и не обращается к HID. Во время подтверждения интервал 50 мс, без параллельных запросов.
- `generation` уникально в пределах запущенного Host, включая перезапуски дочернего процесса. Подтверждение требует нового `settings_edit` и совпадения requested/observed. Ручное чтение ждёт нового `read_sequence`; оно не ставится внутрь незавершённой записи.
- Блокирующие IPC исполняются в `spawn_blocking`. После `Open` с полноценным состоянием повторное полное чтение не запускается.

## Измерение на реальной клавиатуре

Один и тот же IO White 1.17. Контролируемая проверка меняет только яркость на один шаг, подтверждает чтением и возвращает точное исходное значение. Во время проверки наблюдение глубины выключено, приложение закрыто; отдельные каталоги recovery сохранены локально. Измеряется RPC нативного провайдера, включая резервный снимок и readback, но без UI/SQLite/кадра браузера.

| Операция | До | После |
|---|---:|---:|
| Запись тестовой яркости с подтверждением | 642,228 мс | 51,495 мс |
| Возврат исходной яркости с подтверждением | 638,213 мс | 51,388 мс |
| Явное полное чтение | 198,564–202,142 мс | 200,285–202,416 мс |
| Обменов на обычную запись света | 152 | 4 |

Это два контролируемых изменения, а не распределение задержек или гарантия кадрового времени. Новый provider сообщил около 35 мс для самой SET с обратным чтением; резервный снимок около 4 мс, сохранение intent около 1 мс. Исходная яркость восстановлена после обоих запусков. Назначения, срабатывание, калибровка и firmware не менялись.

## Проверки

Очередь проверяется задержанными ответами: первый и последний цвет, отсутствие накопления промежуточных цветов, отказ без повторов, закрытие до отправки следующего состояния, объединение цветов разных клавиш. Host проверяется настоящим mock-процессом с задержанным SET и независимым вторым экземпляром: Core/статус остаются доступны, лишнего GET нет, чтение ждёт записи, счётчики не обновляются оптимистически. Отдельная регрессия перезапуска процесса исключает подтверждение старой очереди новым подключением.

Native provider проверяет число обменов, строгий readback, durable snapshot/intent, холодное восстановление ограниченного снимка с сохранением внешних изменений других групп. Видимый цвет и реальное время обновления LED не выводятся из ACK или этого замера.

В итоговой release-сборке на подключённом IO проверены выбор двух цветов палитры и жест HSV: поля доступны во время незавершённой записи, итог подтверждается без ошибки. Исходный цвет возвращён через HEX и подтверждён отдельным ручным чтением. Кнопка чтения после завершения остаётся доступной при фоновом опросе. Изолированный native smoke установки/обновления/удаления mock-провайдера также прошёл, без доступа к оборудованию.
