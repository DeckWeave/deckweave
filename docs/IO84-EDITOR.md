# Редактор IO Type 84 и глубина нажатия

Изменения 2026-11-02 после замечаний владельца. «Действия / Освещение / Настройки устройства» перенесены в общую шапку редактора; второй ряд удалён. Переключение через шестерёнку синхронизирует активную вкладку. Шапка остаётся доступна при прокрутке настроек.

Раскладка сохраняет прежние физические ID. Правый Shift оканчивается на x=904, как Enter, Backspace и Backslash, вместо выступа до x=908. Добавлена физическая LED-панель справа между PgDn и стрелкой вверх. Она показана нейтрально во всех трёх превью: фактические цвета и прямой setter панели не установлены, поэтому это пассивная геометрия, а не экран, touch target или назначаемая кнопка.

## Наблюдение глубины

Для подключённого IO в шапке доступна кнопка **«Глубина»**. Она явно включает временную телеметрию 66/67; назначения и обычная печать не перехватываются. Поддержка наблюдения объявляется драйвером отдельно от цифровых событий и действий DeckWeave. При открытии приложения режим не включается автоматически.

На клавишах во вкладках Действия, Освещение и Настройки появляются круговые индикаторы свежего хода. В настройках одной выбранной клавиши также показано значение в миллиметрах. Рядом с «Глубина» выбирается **шкала 3,2 / 4,0 мм**; начальная шкала 3,2 мм соответствует старому прототипу. Это только представление, без изменения срабатывания или калибровки. Значение в миллиметрах сохраняется, даже если круг достиг предела. Ранее 3,2 мм на шкале 4 мм выглядели как 80%, поэтому заполнение само по себе не доказывало ограничение измерения.

Во вкладке действий снят предел 570 px для клавиатуры: превью занимает доступную область. «По размеру» и масштаб 75–150% позволяют рассмотреть подписи и кольца; при увеличении доступна прокрутка. Геометрия Mirabox не меняется.

## Подсветка и выбор цвета

Редактор показывает большую клавиатуру, выбор эффекта и только относящиеся к нему параметры. Яркость и скорость задаются ползунками; единый цвет — HSV-полем, оттенком, HEX или готовым образцом. Во время движения указателя меняется локальный образец; отпускание отправляет один RGB patch целиком. Отмена pointer gesture и уход из компонента очищают локальный образец. Пресеты и привязка к профилю свёрнуты ниже основной настройки; при проверке записи сохранение пресета недоступно.

Параметры описывает драйвер через `colorChannels`, `visibleWhen` и `presentation`; UI не содержит особых ID IO84. Условия вычисляются по считанным значениям. Сохранение пресета исключает параметры, недоступные в текущем эффекте, и не подменяет считанное состояние неподтверждённым запросом.

Во вкладке индивидуальных цветов по-прежнему доступен только подтверждённый адрес Esc. Запись требует режима индивидуальной подсветки; переход на вкладку сам режим не меняет. Превью общего эффекта показывает образец цвета, а не симуляцию анимации. LED-панель остаётся пассивной.

Официальный [веб-драйвер IO](https://web.io.vision/) изучен по открытой странице и поставленным JavaScript-модулям: цвет предварительно отображается во время выбора и записывается по завершении; доступные параметры зависят от эффекта. Полный аппаратный интерфейс в браузере не пройден: страница требует подключения через WebHID. В DeckWeave приняты эти принципы взаимодействия, без копирования исходного кода.

## Исправление проверки записи

Ошибка владельца затронула переключение `colorMode` с 1 на 0. Старая GET13 возвращает вычисленное состояние эффекта: в White 1.17 цвет и режим могут отличаться от сохранённых байтов после успешной SET23. Сравнивать этот ответ с отправленным блоком было неправильно.

Для точно проверенной White 1.17 сохранённые 16 байт читаются GET12 по смещению 0x0200. Этот адрес подтверждён точным кодом прошивки и физическим GET без записи. Новые снимки помечаются происхождением; сравнение остаётся строгим, с учётом обязательных маркеров протокола. Старый снимок из GET13 не используется для восстановления неизвестных исходных цветов.

Если свежее чтение полностью совпадает с запрошенным изменением, проверка предлагает **«Принять сохранённые изменения»**: это отдельное явное действие без новой аппаратной записи. Токен ограничен выбранным экземпляром и сроком; повторное чтение перед принятием должно снова совпасть. Исходный снимок и история сохраняются. Несовпадение не обходится и не вызывает автоматической повторной SET.

В native release пройдено принятие прежнего результата без SET, затем смена эффекта, выбор палитры, обычный ввод HEX с Enter и HSV drag. Четыре новые записи используют сохранённый блок schema 2; pending отсутствуют. На окне 1182×891 клавиатура слева, параметры и HSV/HEX справа видны одновременно. [Итог проверки](evidence/2026-11-02/io84-lighting-refinement.json). Последний проверенный цвет — `#2C74A2`, эффект статичный; видимый оттенок и новый масштаб глубины ещё оценивает владелец.

Нет свежего измерения — нет индикатора и числовое значение «—». Только полученный нулевой отсчёт означает ноль; через 600 мс устаревшее значение становится неизвестным. Измерения не исполняют назначенные действия и не записываются в SQLite/историю нажатий.

UI читает отдельный ограниченный snapshot с частотой до 20 Гц, provider объединяет данные до 30 Гц. Полная конфигурация/изображения не пересылаются для каждого отсчёта. Закрытие окна снимает его подписку; если UI перестал отвечать, программная аренда истекает через 3 секунды. Драйвер также контролирует собственную аренду и завершение stdin. Жёсткое завершение процесса не является доказательством аппаратной остановки: программного finally после него нет, а аппаратный TTL не установлен. Это режим наблюдения, не эксклюзивный захват ввода.

## Что проверено

Svelte, форматирование, Clippy и regression suites; диапазоны descriptor, пассивность LED metadata, реальные два provider instances, независимая последовательность telemetry, поколения, TTL/lease и закрытие. Пропавшие/неправильные измерения не заменяются нулём. В native UI подтверждены шапка, новый край Shift, видимая LED-панель, обновление descriptor через сохранённый экземпляр и включение наблюдения без ошибки: [результат](evidence/2026-11-02/io-editor-ui.json).

На реальном IO White 1.17 проверены: start66, чтение настроек во время наблюдения, stop67 с ACK, следующее чтение, повторное включение, отсутствие heartbeat 3,4 секунды, остановка драйвером и закрытие. Получены 157 свежих samples без сохранения истории. SET назначений/освещения, capture, reset и firmware-команды не отправлялись. Обнаруженный непрочитанный ACK67 исправлен; строгая проверка GET сохранена. [Свидетельство](evidence/2026-11-02/io-type-84-observation.json).

## Результат проверки владельцем и оставшаяся приёмка

Владелец подтвердил обычную печать при наблюдении и заполнение кругов при нажатии. Точность соответствия всех клавиш не принята: прежнее превью было слишком маленьким, а заполнение выглядело ограниченным 80%.

После обновления достаточно проверить читаемость клавиатуры и плавное показание в мм на одной выбранной клавише, затем выбрать произвольный единый цвет и оценить его на реальной подсветке. Повторять принятую обычную печать и проверять все 84 клавиши для этой правки не требуется. Полное покрытие адресов по-прежнему не заявляется.

Для проверки новой геометрии не нужно менять настройки устройства. Если после перезапуска IO указан вне сети, используйте Настройки → Устройства → Обнаруженное оборудование и сопоставьте со своим сохранённым IO. Это сохраняет профили и обновляет descriptor, включая новую геометрию и capability наблюдения.
