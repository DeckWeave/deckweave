# Аппаратные назначения клавиатуры и действия DeckWeave

Основной слой и Fn читаются из клавиатуры. Строка **«В клавиатуре»** показывает считанное назначение, а строка **DeckWeave** — действие выбранного профиля. Неизвестное назначение сохраняется и показывается как неизвестное; положение клавиши не используется для догадки о её функции.

Аппаратное назначение общее для всех профилей. Например, одна физическая Fn+T может запускать редактор в Work и действие OBS в Streaming: клавиатура отправляет один и тот же служебный сигнал, а DeckWeave выбирает действие текущего профиля. Переключение профиля не переписывает память клавиатуры. Если в профиле действия нет, ничего не запускается и прежняя аппаратная функция автоматически не возвращается.

## Как назначить действие

1. Откройте редактор IO84 → **«Действия»**, выберите **«Основной»** или **Fn** и нужную клавишу.
2. Перетащите действие из библиотеки. При первом переходе к исполнению в DeckWeave появится предложение с прежним аппаратным назначением и новым действием.
3. Нажмите **«Использовать DeckWeave»**. Приложение само выбирает свободный F13–F24, сохраняет действие и резервирует аппаратный источник до записи. Адаптер записывает назначение и проверяет его чтением. Затем настройте параметры действия в инспекторе.

Служебный F-код не нужно выбирать вручную. На одну подтверждённую клавиатуру доступно двенадцать независимых источников: пул общий для Основного слоя и Fn. Один источник может использовать разные действия в разных профилях. Занятые аппаратные коды, неактивные профили и незавершённые операции учитываются при распределении; при исчерпании пула приложение сообщает об этом, а не переиспользует чужой код.

Fn-действие хранится на уровне профиля и доступно на всех его страницах. Действие Основного слоя использует обычное назначение выбранной страницы. Сама клавиша Fn не является отдельным доступным событием для запуска действий.

Сохранённая ранее Fn+T с запуском `notepad.exe` остаётся на месте. Если аппаратная часть ещё не настроена, выберите эту клавишу и нажмите **«Завершить настройку привязки»**: появится то же предложение замены. Удалять и создавать действие заново не требуется. Этот переход доступен только для считанного, поддерживаемого аппаратного назначения; наличие прежнего F-кода само по себе не доказывает владение им или знание исходной функции.

После настройки существующего источника изменение его действия в другом профиле не требует новой аппаратной записи. После полного завершения DeckWeave клавиатура продолжает отправлять служебный F-код, но действие приложения не выполняется. Закрытие окна редактора оставляет фоновый runtime в трее. F-коды остаются обычным клавиатурным вводом и могут быть видны другим программам; скрытие этих кодов не реализовано.

## Удаление действия и возврат аппаратной функции

**Удалить действие** убирает действие текущего профиля. Служебный сигнал остаётся в клавиатуре, его резерв сохраняется. В профилях с другими действиями этот источник продолжает работать; в текущем профиле отображается, что действия нет.

**«Аппаратная привязка» → «Восстановить назначение клавиатуры…»** — отдельная операция. Перед подтверждением показаны затронутые профили. Их действия сохраняются, но перестают запускаться этой клавишей. Точные исходные байты возвращаются только тогда, когда текущее назначение всё ещё совпадает с установленным DeckWeave. Проверенное чтением восстановление освобождает код. Если запись была отменена до установки и полное чтение подтверждает исходное состояние без этого сигнала, резерв можно снять без SET.

Внешнее изменение этой же клавиши не затирается сохранённым оригиналом. Вместо этого остаётся конфликт для проверки. Если исходное назначение неизвестно, автоматического восстановления нет. Удалить сохранённый экземпляр окончательно нельзя, пока у него остаются незавершённые аппаратные резервы.

## Что означают состояния

| Состояние | Что уже установлено |
| --- | --- |
| «Выполняется клавиатурой» | Прочитано штатное назначение; действие DeckWeave не требуется |
| «Действие сохранено; аппаратная привязка не подтверждена» | Есть настройка приложения, но физический запуск ещё не готов |
| «Запись и проверка назначения…» | Сохранена операция, выполняется запись с чтением результата |
| «Аппаратная привязка подтверждена; источник ввода недоступен» | Байты совпали, но подтверждённого маршрута ввода нет |
| «Источник ввода подключён» | Проверены назначение и программный источник; это ещё не физическая приёмка |
| «Нужно проверить состояние клавиатуры» | Результат записи или соответствие текущему экземпляру требует явной проверки |

После повторного сопоставления устройства или неопределённой записи используйте **«Проверить привязку клавиатуры»**. Это явное чтение и сверка сохранённой операции с выбранным подключённым экземпляром. Оно не повторяет SET. Открытие редактора, запуск приложения и переподключение сами не продолжают незавершённую аппаратную запись. Одного совпадения модели или VID/PID недостаточно для переноса прежних оригиналов на другое устройство.

Кнопка **«Проверить»** в редакторе выполняет действие программно. Она помогает проверить параметры запуска или плагина, но не доказывает работу Fn, USB или физического источника ввода.

## Реализация и границы первого среза

Владение хранится в `Device.keyboard_aliases`, отдельно от профилей. Запись содержит слой, физическую клавишу, F-код, точные исходные и установленные четыре байта, идентификаторы установки и текущей операции, происхождение, состояние и сведения о подтверждённом сеансе. Fn продолжает использовать `profile.fn_bindings`; Основной слой — обычные `Binding` страницы. Миграция сохраняет старые действия как непроверенные ссылки, не выполняя аппаратных операций.

Формат конфигурации и SQLite `user_version` равны 3. Перед миграцией создаётся долговечная копия `*.pre-v3-r…sqlite3`; неизвестные JSON-поля сохраняются. Старый уже открытый writer отклоняется SQL-ограничением, а старый исполняемый файл не должен открывать новую версию базы. Откат базы или программы не восстанавливает память клавиатуры.

`installKeyboardAlias`, `restoreKeyboardAlias` и `reconcileKeyboardAlias` идут отдельным путём адаптера, а не через очередь обычных настроек. Установка резервирует источник и сохраняет действие до SET; завершение требует подходящего поколения соединения, исхода операции и чтения результата. Транспорт меняет полный блок слоя с сохранением остальных записей. Неопределённый исход удерживает резерв и не запускается повторно автоматически.

Windows Raw Input работает в отдельном процессе провайдера и принимает только настроенные сигналы подтверждённого устройства. Новый путь не переключается на глобальные горячие клавиши при ошибке. Сохранённое состояние `verified` после перезапуска не даёт готового маршрута: нужна явная проверка текущего сеанса. Очередь использует поколение соединения, профиль, источник, операцию и отпечаток содержимого действия; изменение параметров с тем же ID также делает прежнее событие недействительным. Источник не сохраняет историю обычной печати.

Текущий режим — одна логическая активация. Плагины получают немедленную совместимую пару `keyDown`/`keyUp`; физическое удержание и отпускание этим не подтверждаются. Key Logic, удержание и двойное нажатие для этого пути остаются обязательным следующим этапом после проверки физических Down/Up и их жизненного цикла. Самостоятельное событие Fn не предполагается.

Автоматическая замена сейчас ограничена обычными одиночными клавиатурными USB-назначениями, включая стандартные модификаторы. Функции подсветки, мыши, мультимедиа, комбинации, макросы, DKS и парные назначения не получили нового общего writer: их считанные значения можно видеть, а расширять запись нужно отдельно по возможностям адаптера. Неизвестные, режимные и неподтверждённые записи остаются только для просмотра. Временные световые уведомления используют [отдельный RAM-канал](KEYBOARD-ACTIONS.md#таймер--красное-мигание-t).

Они не заменяют аппаратную приёмку.

Физический запуск нового пути ещё не принят. После подготовки сборки нужна одна новая проверка: нажать **Fn+T** и подтвердить однократный запуск сохранённой программы. Программная кнопка «Проверить» и состояние подключённого источника эту проверку не заменяют; ранее принятую печать и Mirabox повторять для неё не требуется.
