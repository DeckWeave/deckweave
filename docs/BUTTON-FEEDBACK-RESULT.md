# Исчезновение кнопок после нажатия

Исправлено 3 ноября 2026. Назначения не удалялись: после ошибки действия хост
исключал изображение плагина из кадра, а плагины с готовой подписью на картинке
оставляли текстовый заголовок пустым. В результате кнопка становилась чёрной.

Теперь изображение сохраняется при ошибке, а физический экран получает небольшой
предупреждающий значок. Без изображения используется название назначения.
Следующее успешное выполнение восстанавливает обычную картинку. Это работает
также для сенсорной полосы и не меняет прежний формат JPEG Mirabox.

У Workspace обнаружена и исправлена причина ошибки запуска VS Code: Windows
иногда отклоняла обычную активацию окна из фонового обработчика HID. Добавлена
одна попытка активации с временным присоединением очереди ввода переднего окна.
Присоединение завершается до проверки результата и отправки сочетаний клавиш.
Проверяются точное окно и executable; при смене переднего окна или удержании
модификаторов этот обход не применяется. Настройки Windows не меняются.

SDK поддерживает необязательный текст `showAlert(message)`. Workspace передаёт
конкретную причину в инспектор вместо общего сообщения, сохраняя совместимость
с существующим вызовом `showAlert()`.

## Что проверено

- Полная `npm run check`: Svelte, форматирование, web-сборка, Rust workspace,
  тесты плагинов, сервисов, настройки личного профиля и документация.
- После изменения активации: тесты `deckweave-workspace`, clippy всего workspace
  с запретом предупреждений и `npm run test:workspace` повторно прошли.
- SDK: 29 тестов; шаблон: 3 теста; реестр: 10 тестов и проверка комплектации.
- Нативный тест через настоящий процесс Workspace, SDK, хост и ядро: ошибка
  сохраняет картинку, успешное повторение восстанавливает её, назначения
  остаются прежними. Только запуск внешнего приложения заменён тестовым ответом.
  [Результат](evidence/2026-11-03/button-feedback-native-smoke.json).
- Проверка рендера сравнивает JPEG до ошибки, с предупреждением и после
  восстановления для кнопки и полосы; проверяется сброс кэша при смене статуса.
- В рабочей release-сборке через «Проверить» действительно открыты Zotero и
  VS Code. Ранее ошибавшаяся кнопка VS Code восстановилась после успешного
  запуска. Все десять кнопок и полоса видны в редакторе, Mirabox подключён.
- Настоящий VS Code в отдельном тестовом каталоге: активация production helper,
  аутентификация канала, наличие десяти команд, четыре изменения Typst и их
  отмена. Личные документы не менялись; команды агента Codex не запускались.
  [Результат](../integrations/vscode/evidence/2026-11-03-fixture.json).

Физические нажатия и сами экраны устройства в этом прогоне не наблюдались.
Проверена отправляемая отрисовка и работа приложения; читаемость на устройстве
и комфортность звука остаются пунктами [личной приёмки](PERSONAL-WORKSPACE.md).
