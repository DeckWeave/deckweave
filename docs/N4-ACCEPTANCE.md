# Первая аппаратная проверка N4 Pro

Дата: 2026-11-01. Устройство обнаружено как VID 5548/PID 1021, interface 0, FFA0:1. StreamDock и старый DeckWeave закрыты. Работает новый `target/release/deckweave-desktop.exe`.

## Подтверждено программно

- Новый scan находит один N4 identity по USB serial; соседние keyboard/consumer collections не открываются.
- Реестр автоматически создал отдельный аппаратный instance, соединение generation 1, без ошибки.
- Переданы 10 JPEG по 112×112 через BAT/chunks/STP. Preview показывает те же байты с обратным поворотом.
- Выбор K1 ничего не выполняет. «Проверить» увеличил Counter до 1 и передал pressed/result кадры; input_events остался 0, поскольку это UI ввод.
- Добавление страницы 2 отправило 10 пустых кадров; возврат на страницу 1 отправил 10 исходных кадров. Итого в первой сессии 32 успешных передачи, без reconnect/error.
- Закрытие редактора сняло editing pause и оставило соединение подключённым, generation 1.
- Полный restart release-сборки сохранил тот же instance ID, две страницы и выбранную страницу 1; повторно передал 10 начальных кадров без ошибки. Runtime Counter ожидаемо сбросился в 0.
- Автоматические тесты проверяют повторную регистрацию/restart identity, stale generation, held cleanup, пересечение UI/hardware источников, независимость instances, malformed packets, порядок/размеры транзакции, JPEG с кириллицей и отсутствие starvation других кнопок.

[Первая диагностическая сессия](evidence/2026-11-01/n4-first-session.json). Эти свидетельства подтверждают transport/runtime, но не физическую карту кнопок или визуальное содержимое аппаратных экранов.

## Результат первой физической проверки владельцем

Владелец подтвердил: изображения соответствуют кнопкам; K6–K10 увеличивают счётчики на устройстве и в UI; первая крутилка увеличивает/уменьшает значение по направлению и прибавляет 1 при Click. Верхний ряд K1–K5 ошибочно менял сенсорные области. Сенсорная полоса была пустой и не исполняла касания.

[Захват первой проверки](evidence/2026-11-01/n4-owner-first-input.json) показал физические keys raw 1–10. Ошибка возникла из-за применения адресов BAT к входу; исправлена отдельной картой. Regression replay проверяет 20 записанных key edges через decoder → runtime: K1–K10 исполняют key actions, touch feedback не меняется. Прежние decoded labels полного захвата не изменялись: они показывают ошибку старой сборки.

В захвате есть touch down code 00/state 01 с X, ARX samples и завершение code 00/state 00 либо 40–43/state 00. Добавлены single-contact adapter и volatile BGPIC 800×128 output. Простой strip renderer показывает T1–T5 и значения D1–D4; UI использует тот же JPEG и ту же геометрию для областей. Это тестовый hardware slice, а не полноценные panel plugins/Dial Stack/Action Wheel.

Исправленная release-сборка прошла 32 теста и native запуск. Подключение generation 1 без ошибок, 28 успешных кадров: 11 начальных, 11 при возврате с пустой страницы на страницу 1, четыре при T1 OFF→ON→OFF через UI, два при D1 0→1→0. На preview индикатор D1 менялся вместе со значением крутилки. Все три страницы владельца сохранены, runtime значения возвращены в исходное состояние. [Сборка/состояние](evidence/2026-11-01/n4-touch-build.json), [preview полосы](evidence/2026-11-01/n4-touch-editor.jpg). После этого запрошена повторная физическая приёмка; её результат приведён ниже.

## Повторная физическая проверка — подтверждена владельцем

На перечисленные ниже проверки владелец ответил: «Все перечисленное работает». Подтверждены исправленный верхний ряд, изображение/ориентация полосы, крайние T1/T5, отображение D1 при вращении. [Захват повторной проверки](evidence/2026-11-01/n4-owner-retest.json): 162 входа, 167 выходных кадров, generation 1 без ошибок. Это не подтверждает оставшиеся D2–D4, USB reconnect или все жесты.

После финального запуска оставить открытым редактор N4, страницу 1. Нумерация слева направо: верхний ряд K1–K5, нижний K6–K10. K2 — Toggle, остальные — Counter. После restart значения Counter = 0 и K2 = OFF.

1. Повторить верхний ряд: дважды K1 → 2; K2 → ON. Проверить, что touch области от этих кнопок не меняются. K6–K10 уже подтверждены, их карту не меняли.
2. На полосе должны появиться T1–T5 и значения D1–D4. Проверить ориентацию и расположение. Нажать левую, затем правую область: должны переключаться T1 и T5 на устройстве и в UI. Движение по полосе отменяет нажатие и не должно переключать область как обычный tap.
3. Повернуть первую крутилку на несколько делений вправо и влево, затем нажать её один раз. События будут записаны; Counter D1 отображается в редакторе. Подтверждённого release/hold крутилки пока нет, поэтому press — отдельный Click.
4. Сообщить, что видно на экранах и совпала ли позиция. Если не совпала — указать физически нажатую кнопку; raw trace позволит исправить соответствие.

Следующие аппаратные проверки: оставшиеся крутилки, USB reconnect и движение/отмена касания. Не заявлять их проверенными по одному только тесту декодера. Native panel plugins, произвольные элементы по двум координатам и полная gesture arbitration реализуются отдельным этапом. Текущий adapter рассчитывает адресата Down по X в областях полной высоты; ARX Y используется для отмены движения. Timeout 3 секунды отменяет незавершённый контакт, не исполняя hold.

После приёмки владелец заметил сжатую по высоте полосу в UI при правильном аппаратном изображении. Исправлена логическая геометрия: вместо 556×64 preview surface использует 556×88,96 (800:128), dials сдвинуты вниз. Масштаб всей модели вычисляется из geometry конкретного instance вместо фиксированного 608:448.

Изменение проверено в новой release-сборке: [native screenshot](evidence/2026-11-01/n4-preview-ratio-fixed.jpg), [соотношение 6,25 и состояние сборки](evidence/2026-11-01/n4-preview-ratio-fixed.json). 32 теста проходят; окно открыто на странице 1, connection generation 1 без ошибки. Аппаратные normalized rectangles/пакеты не менялись.

## Диагностика и повторный запуск

Текущие snapshot и до 256 последних raw/decoded входов находятся рядом с `deckweave.sqlite3` в app data каталоге `app.deckweave.studio`, файл `n4-diagnostics.json`. Это диагностический снимок, не сохранение runtime counters/pressed. JSON обновляется при изменениях с ограничением частоты; после restart файл относится к новой сессии.

Не запускать StreamDock одновременно. HID open может быть разделяемым: один управляющий процесс — условие проверки, а не доказанная гарантия эксклюзивного доступа. Приложение пока завершается при закрытии всех окон; tray остаётся в [плане](PLAN.md).
