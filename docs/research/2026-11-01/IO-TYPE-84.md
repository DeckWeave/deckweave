# Основа будущего provider IO Type 84

Дата просмотра: 2026-11-01. Источник — существующий проект `G:\APPS\io_type_84`, его исходники и сохранённые свидетельства. В этом исследовании клавиатура не открывалась через HID, команды не отправлялись и проверки не повторялись. Драйвер откладывается по решению владельца.

## Что уже есть

Проект использует Rust + Tauri + Vue. `io-core` отделён от `io-platform`; UI для переноса в Svelte не нужен. Изучены `docs/STATUS.md`, `docs/PROTOCOL.md`, `modules/exclusive-depth.md`, записи аппаратной приёмки и выбранные исходники.

| Уровень | Основа в прототипе | Граница подтверждения |
|---|---|---|
| USB | `io-platform/src/device.rs`, `protocol.rs`: AA/55, отдельный HID-интерфейс, проверка descriptor/firmware, очередь уведомлений среди ответов | Конкретная IO Type 84 Magnetic White 1.17; не универсальный драйвер всех вариантов |
| Конфигурация клавиш | `BindingRecord`, base/Fn, actuation/rapid trigger, цвет, DKS, hardware macros | SET/readback не равен проверке физического исполнения всех типов назначений |
| Всё устройство | `LightingSettings`, `PerformanceSettings`, snapshot/revision, планы изменений | Эти параметры должны иметь отдельную форму, а не повторяться в инспекторе каждого действия |
| Наблюдение | `KeyTravel`: slot, travel/max в мкм, ADC, age; `MonitorFrame` | Есть документированный физический полный ход двух клавиш, не приёмка всей матрицы |
| Захват и восстановление | `input_ownership.rs`, `exclusive_depth.rs`: снимок base/Fn и журнал восстановления | Stock adapter ограничен слотами 105/108; захват не имеет аппаратного TTL |
| Временный RGB | `stream_key_rgb`, один HID worker, команда 0x32, 1–14 клавиш в кадре | По STATUS: mode 1/20, RAM-only; отправка кадров подтверждена, цвет после последнего transport fix глазами ещё не принят; полоса не управляется этим API |

В `docs/evidence/stock-capture-acceptance-v1.17.json` от 2026-09-14 приняты контроль до/после, отсутствие исходного цифрового выхода выбранных клавиш, живой контроль наблюдателя и возврат снимка. В измерении PgUp/PgDn достигают примерно **3,97 / 3,96 mm**. Это более позднее и сильное свидетельство, чем ранняя запись с небольшим ходом. Оно ограничено двумя клавишами, выбранными маршрутами и White 1.17; power-cycle persistence не проверена.

Следовательно, получение глубины — уже подтверждённая возможность прототипа в ограниченной области. Нет оснований обещать аппаратную готовность всех 84 клавиш или перенос всех gesture/lighting функций без отдельной приёмки.

## Что потребуется адаптировать

1. `NativeDevice::open()` ищет ровно одно совпадение и возвращает ошибку при нескольких клавиатурах. Новый provider должен перечислять устройства и открывать выбранный instance по его идентичности/пути. Совпадение модели не равно идентичности экземпляра.
2. VID/PID — **0C45:80D6**; **FF68:0061 — usage page / usage**, не VID/PID. Нельзя путать эти пары при обнаружении устройств.
3. Разделять физические клавиши (84), слоты конфигурации (128), аппаратные LED-адреса и control IDs нового host. Предоставить явные отображения вместо одинаковых индексов по предположению.
4. Сохранить raw analog samples с единицами и свежестью отдельно от digital input. Key Logic DeckWeave не должен автоматически превращать каждый analog sample в keyDown.
5. Обычные назначения действий DeckWeave сохраняются автоматически. Отдельная операция записи onboard-параметров может требовать плана аппаратных изменений и восстановления; старый UX черновиков всего приложения переносить не следует.
6. Временный захват требует отдельного явного состояния и восстановления после crash/unplug. Отсутствие аппаратного TTL у переназначения нельзя скрыть обещанием мгновенного возврата исходных клавиш.
7. Возможности включаются по конкретному capability и версии протокола. Появление поля в DTO или ACK не является аппаратной приёмкой.

## Полезная готовая OBS-основа

`io-platform/src/obs.rs` уже содержит небольшой obs-websocket v5 клиент: Hello/Identify, challenge authentication, `GetRecordStatus`, ограничение свежести и остановку worker. Это read-only источник для localhost, не готовый плагин всех OBS-действий. Его можно использовать как референс и fixture для проверки соединения; полноценному плагину потребуются собственные команды, события и lifecycle. В этой сессии OBS не подключался и настройки его WebSocket-сервера не менялись.

## Следующий объём

Сейчас достаточно зарезервировать в hardware API независимые instances, геометрию, digital/encoder input, необязательное analog observation и отдельные device-wide settings. Реализацию клавиатуры, onboard-запись, RGB, мышь и их специальные редакторы не добавлять в первый сквозной N4-срез.
