# Исследование нового DeckWeave

Дата: 2026-11-01, часовой пояс владельца — Asia/Yekaterinburg.

Статус: исследовательский пакет перед проектированием. Владелец ответил на вопросы и принял стек и продуктовые требования — актуальный список в [DECISIONS](../../DECISIONS.md). Предложения исследователя не являются утверждённой архитектурой, планом реализации или обещанием совместимости.

После замечаний владельца исследование продолжено: настройки составных действий были осмотрены, но их исполнение и смена самой кнопки ещё не проверены. Сначала нужны дополнительные трассы поведения. Dial Stack и Action Wheel теперь обязательны в первом полноценном выпуске; раннее откладывание Dial Stack отменено.

Последние ответы владельца закрывают Q-15–Q-17: настройки останавливают Smart Profiles глобально; сенсорная панель нужна и самостоятельная с виджетами/своей раскладкой, и связанная с крутилками, с размещением совместимых действий в областях; импорт старых профилей и миграция конфигураций не нужны, Elgato-плагины нужны. Раннее предложение ограничиться полосой по крутилкам отклонено. Недоступность эталонного оборудования не мешает начать основу приложения.

## Основные результаты

1. Для исходных HTML-форм Elgato нужен браузерный движок. У установленного On Air Clock HTML используется также для самого работающего плагина, поэтому закрытие редактора не позволяет автоматически выключить весь браузерный runtime.
2. Владелец принял **Rust + Tauri 2 + Svelte**. Это выбор по сложности реализации совместимого редактора, а не доказанная победа в скорости или расходе памяти. Численные ограничения владелец не задаёт; контролируем нагрузку измерениями типовых сценариев.
3. Опасение по ресурсам обоснованно. Старый host с одним HTML-плагином часов потреблял около 180 МиБ private commit; два независимых окружения — около 351–364 МиБ. Общее временное окружение снизило показатель до 221–231 МиБ, но один сеанс завершился ошибкой при остановке другого. Такой способ совместного запуска пока непригоден для переноса.
4. On Air Clock 1.3.0 выдаёт настоящие PNG 144×144 через старый совместимый host; Visual Studio Code 5.1.3 регистрируется и отдаёт настройки. Архивный OBS 2.2.4 регистрируется. Это разные частичные результаты, а не полноценная приёмка интеграций.
5. В старом редакторе подтверждены отдельные состояния черновика, применённого документа и навигации редактора/устройства. Это объясняет возможный разрыв между интерфейсом и железом. Точный пользовательский сбой на сохранённой конфигурации не воспроизводился.
6. Для переноса наиболее полезны низкоуровневый N4-транспорт, декодеры, тестовые пакеты и отдельные Windows API-адаптеры. Общий граф автоматизаций, редактор сцен и пользовательскую процедуру apply предлагается пересобрать под новую задачу.
7. Следующая клавиатура — IO Type 84. Изучен прототип: есть onboard-настройки, RGB и наблюдение глубины; сохранённая аппаратная приёмка подтверждает полный ход двух клавиш White 1.17. Полная матрица не проверена. Текущий USB-адаптер требует переработки для нескольких instances. [Разбор](IO-TYPE-84.md).
8. Выполнен подробный [обход Stream Deck](STREAM-DECK-WALKTHROUGH.md): новый лабораторный профиль, страницы/папка, Multi Action/Delay/Switch, Key Logic, pinned actions, все вкладки Preferences и Marketplace. Смена циферблата On Air Clock сразу обновила кнопку и инспектор без Apply. Физический вывод и исполнение составных действий не проверены.
9. Уточнены различия Switch, состояний action и Key Logic, связь Encoder с участком touch strip, Dial Stack и Action Wheel по первичным документам Elgato. [Разбор](ADVANCED-INTERACTIONS.md). Просмотрены три скриншота владельца.
10. Изучены Ajazz и публичные SDK Mirabox, просмотрены режимы крутилок установленного StreamDock. В Ajazz найдены конкретные ограничения desired-state и touch hold. [Сравнение](REFERENCE-IMPLEMENTATIONS.md). Три заданных видео открыты, но воспроизведение и transcript недоступны; просмотр не заявляется. [Статус видео](VIDEO-REVIEW.md).

## Что уже определил владелец

- Максимально близкий к Elgato редактор вначале; улучшения — после стабильной базовой версии.
- Реестр поддерживаемых и подключённых устройств; из записи устройства открывается его полноценное окно.
- Один обработчик оборудования должен обслуживать несколько экземпляров устройств.
- Плагин оборудования описывает взаимодействие с железом и геометрию его элементов.
- Вначале обычные назначения кнопок/энкодеров и областей дисплея; свободный canvas не является приоритетом.
- Нужны видимые физические нажатия, виртуальное выполнение и проверяемая связь назначения с результатом.
- Черновики и ручное применение не должны быть обязательными шагами обычной настройки.
- Первое оборудование — Mirabox N4 Pro; далее клавиатура, мышь и позднее Android-панель.
- Уровень совместимости и доступные версии плагинов OpenDeck подходят; тестовый набор — установленные плагины и OBS.
- Первые сценарии: навигация, запуск программ, простые виджеты и действия Elgato.
- Первая ОС — Windows 11; приложение должно допускать развитие под macOS/Linux.
- Новый код находится в `G:\APPS\DW\deckweave`; SDK, шаблоны и реестр — соседние репозитории.

## Границы исследования

Новый продукт, SDK и плагины не написаны. Старые исходники не изменены. Backend-пробы выполнялись на временных копиях пакетов, с виртуальной кнопкой и пустыми настройками. В официальном Stream Deck создан и оставлен отдельный профиль DeckWeave UX Lab; после обхода восстановлен Default Profile / страница 2. Полный список изменений — в walkthrough. Физические USB-сессии N4 и IO Type 84 не открывались; запись/трансляция OBS, команды VS Code и действия Codex не запускались. Производительность GPUI непосредственно не измерялась. Совместное WebView-окружение исследовано только диагностическим способом, без реализации корректного общего владельца.
