# Поведение редактора и приёмка

Дата: 2026-11-01. Это предложение проверяемых сценариев на основе требований владельца, наблюдений и исходников. Сценарии ещё не выполнены на новом приложении.

Принятые требования — в [DECISIONS](../../DECISIONS.md). Подробные фактически пройденные UI-пути и ограничения — в [STREAM-DECK-WALKTHROUGH](STREAM-DECK-WALKTHROUGH.md).

## Что просмотрено в установленном Elgato

Stream Deck 7.6.0.23012, executable `E:\Program Files\Elgato\StreamDeck\StreamDeck.exe`.

- Устройство и профиль выбираются над изображением панели.
- Библиотека действий и поиск находятся справа; страницы — под панелью.
- Одиночный выбор существующей кнопки открывает её настройки снизу. У On Air Clock форма содержит Watchface, форматы даты/времени и цвета.

- Контекстное меню существующей кнопки содержит Pin, Copy, Move to Folder/Multi Action/Key Logic, Import/Export, операции с background и Delete. Команда тестового запуска в просмотренном меню не обнаружена; другие пути тестирования во всём приложении не исследованы.
- В дополнительном обходе создан отдельный DeckWeave UX Lab: страницы, папка, Multi Action/Delay/Switch, Key Logic, закреплённая папка, Timer, Text, Switch Profile и On Air Clock. Проверена немедленная смена циферблата в сетке и инспекторе. После обхода восстановлен Default Profile / страница 2. Существующие назначения не редактировались; временный Style preview возвращён без Apply. Физическая реакция Elgato-устройства не проверялась.

Статьи [Pages](https://help.elgato.com/hc/en-us/articles/4410312027277-Elgato-Stream-Deck-Pages), [Folders](https://help.elgato.com/hc/en-us/articles/360027957912-Elgato-Stream-Deck-Using-Folders), [Multi Action](https://www.elgato.com/us/en/explorer/products/stream-deck/how-to-use-multi-actions/) используются как дополнительные спецификации сценариев; наличие статьи не является проверкой всех функций установленного binary.

## Предлагаемая компоновка

Отдельное небольшое окно реестра: поддерживаемые модели, обнаруженные экземпляры и ранее настроенные offline-устройства. Выбор экземпляра открывает одно его полноценное окно либо поднимает уже открытое.

В окне устройства: сверху профиль/подключение, в центре геометрия конкретного устройства, справа действия, под устройством параметры выбранного назначения. У N4 видны 10 keys, strip и четыре энкодера. Геометрия масштабируется вместе с окном; свободного перемещения оборудования по бесконечному canvas нет.

Подключение/яркость/вибрация находятся в настройках устройства, а не в форме каждой кнопки. Обычное действие сразу показывает предметные параметры. Multi Action открывает список шагов только когда выбран этот тип назначения. Новая универсальная система graph/ports пользователю для простого запуска не нужна.

## Назначение и состояние

Предлагается один сохранённый набор назначений с автоматической записью/обновлением. Внутренние транзакции и revisions допустимы; они не должны становиться обязательной процедурой draft → review → apply для каждого изменения. Ошибка конкретного изменения видна возле поля/назначения, прежнее работавшее состояние не заменяется частично.

Нужно различать четыре независимых визуальных факта: объект выбран для редактирования; физическая кнопка сейчас нажата; действие имеет состояние, например mute; подключение/плагин недоступны. Один цвет или рамка не должны означать все четыре.

Принято владельцем: обычный клик выбирает, отдельная команда «Проверить» запускает. При проверке down/up идут через тот же router, что hardware input; для hold/double нужна явная форма имитации жеста, не скрытое выполнение на выборе. Виртуальное устройство может выполнять реальные действия без физического железа; это должно явно отличаться от изолированного прогона с подменёнными внешними сервисами. [Q-03](QUESTIONS.md).

Для images предлагается общий источник содержимого для preview и hardware output. Иконка в редакторе — последний желаемый кадр; состояние доставки на устройство отдельно. Без аппаратного подтверждения протоколом нельзя подписывать произвольный кадр как «точно показан пользователю».

## Навигация

Профиль — сохранённая конфигурация конкретного устройства. Страницы — верхнеуровневые наборы назначений профиля. Папка — вложенный набор с возвратом. Навигация хранится один раз в runtime instance и отображается UI; не нужны несогласованные индексы для editor/panel/slot.

Принято владельцем: выбор профиля/страницы в окне сразу переключает связанное устройство, аппаратный переход обновляет открытое окно; offline-устройство позволяет редактирование с явным статусом. Скрытый отдельный authoring cursor не нужен.

Документация Elgato описывает auto-added Next/Previous, вложенные папки, выход и pinned actions с локальными переопределениями. Копировать нужно конечное поведение, не число внутренних сущностей. Ограничение на 10 страниц из текущей статьи не обязательно переносить в формат данных навсегда. [Pages](https://help.elgato.com/hc/en-us/articles/4410312027277-Elgato-Stream-Deck-Pages), [Pinned](https://help.elgato.com/hc/en-us/articles/26638431612429-Elgato-Stream-Deck-Pinned-Actions-and-Folders).

Владелец подтвердил: открытие настроек останавливает Smart Profiles всех устройств, дополнительный переключатель режима не нужен. Каждое окно настроек удерживает глобальную паузу, закрытие последнего возобновляет автоматику; обычные действия продолжают работать. В настоящем Preferences Elgato также найдено пояснение об автоматике при закрытом окне. Реестр сам по себе не считается открытыми настройками. Это описание принятого поведения будущего приложения, не результат его реализации. [Q-06 и Q-15](QUESTIONS.md).

Press→смена страницы→release должен быть отдельной приёмкой. Контекст нажатия нельзя молча переопределить контекстом новой страницы. В изученном OpenDeck есть KEY_DOWN_TARGETS, но при отличии текущего context keyUp отбрасывается. Для нового host требуется явно определить cleanup/доставку, не копируя этот участок как универсально правильный.

## Предлагаемая последовательность возможностей

Это порядок демонстрации продукта для обсуждения, не формальный PLAN.md.

1. Реестр, виртуальное устройство и окно, простое назначение, автоматическое сохранение, подсветка ввода и тестовый запуск.
2. Сквозное действие/картинка на N4, reconnect и работа при закрытом редакторе.
3. Страницы, папки и профили с единым runtime состоянием и сохранением после restart.
4. Установка/запуск одного стороннего native/Node и одного HTML-плагина, PI, настройки после restart, images и реальные ошибки.
5. Второй экземпляр устройства в одном provider, два независимых окна, отказ одного устройства/плагина.
6. Multi Action/Delay/Switch, дополнительные Elgato-механизмы, полезные Windows actions и виджеты.

Список не отменяет цель «повторить Elgato». Владелец включил Multi Action/Delay/Switch, Smart Profiles, Key Logic hold/double, pinned actions, Dial Stack и Action Wheel в обязательный объём первого полноценного выпуска; порядок демонстраций не исключает эти возможности. Раннее откладывание Dial Stack отменено. Random и остальные непроверенные детали не следует считать готовыми после появления кнопок и папок. Различия механизмов — в [ADVANCED-INTERACTIONS](ADVANCED-INTERACTIONS.md).
