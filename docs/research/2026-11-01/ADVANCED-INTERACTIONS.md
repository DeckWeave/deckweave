# Составные действия, состояния кнопок, крутилки и touch

Дата: 2026-11-01. Углубление исследования после замечаний владельца. Здесь отдельно отмечены документация Elgato, наблюдения интерфейса и ещё не выполненные runtime-проверки. Это описание референса и требований, не архитектура DeckWeave.

## Что означает «кнопка переключилась на другое действие»

| Механизм | Что выбирается после ввода | Что нужно видеть и проверять |
|---|---|---|
| Multi Action | Один упорядоченный список шагов | Запуск всех шагов с задержками, а не выбор одного |
| Multi Action Switch | Поочерёдно список A и список B | Три нажатия дают A → B → A; сама кнопка имеет различимое представление состояния |
| Двухсостоянийное действие плагина | Состояние одного action instance | Например mute/unmute; состояние может прийти извне, не только от нажатия |
| Key Logic | Ветвь single/double/hold | Жест выбирает ветвь; это не постоянное чередование A/B |
| Dial Stack | Текущее действие крутилки из набора | Нажатие меняет выбранное действие, вращение управляет выбранным |
| Action Wheel | Выбранное клавишное действие в колесе | Выбор и выполнение — разные операции |

Для Multi Action Switch официально описано чередование двух последовательностей на последовательных нажатиях. Точный момент смены состояния и смысл показываемой иконки — текущая/следующая ветвь — требуют исполнения в эталоне; осмотр двух вкладок редактора этого не устанавливает. [Elgato: Switch](https://help.elgato.com/hc/en-us/articles/5162934218637-Elgato-Stream-Deck-4-4-Release-Notes).

Иллюстративный сценарий для проверки требования владельца: A включает рабочий режим и меняет кнопку; следующий запуск на том же месте выполняет B, возвращающий исходный режим и вид. Это будущая проверка, а не уже полученная трасса Elgato. Нельзя после каждого нажатия снова выполнять A, оставляя лишь переключаемую картинку в форме.

## Multi Action и состояние дочернего шага

Multi Action задаёт порядок действий и явных Delay. В документации отдельно указано ограничение на вложенные Multi Action; это не произвольный рекурсивный граф. Очерёдность отправки команд сама по себе не доказывает ожидание завершения операции во внешней программе. [Elgato: Multi Actions](https://help.elgato.com/hc/en-us/articles/360027960912-Elgato-Stream-Deck-Multi-Actions).

У шага есть два разных интервала: между виртуальными down/up и перед следующим действием; опубликованы исходные значения 100/100 мс. Это отличается от добавленного пользователем Delay. Численные пределы в статьях разных поколений расходятся; текущие пределы нужно измерить в установленной версии. [Elgato: задержки](https://help.elgato.com/hc/en-us/articles/7092527123725-Elgato-Stream-Deck-Customizable-Multi-Action-Delays).

В SDK два состояния описываются в manifest; автоматическое переключение можно отключить через `DisableAutomaticStates`, после чего состоянием управляет плагин через `setState`. В составе Multi Action плагин получает `isInMultiAction` и `userDesiredState`: желаемое состояние шага отличается от текущего `state`. Например повторный сценарий «включить свет» не должен случайно выключить его слепым toggle. [Elgato SDK: Keys](https://docs.elgato.com/streamdeck/sdk/guides/keys/).

Практический вывод для исследования: отдельно записывать выбранную ветвь Switch, текущее состояние дочернего action, запрошенное состояние шага и физическое pressed. Эти значения могут различаться. Сбой, busy, повторный запуск и restart должны проверяться как отдельные случаи.

## Key Logic и «два уровня нажатия»

Официальный Key Logic различает одинарное, двойное и длительное нажатие. Это временные жесты обычной кнопки; аналоговая глубина магнитной IO Type 84 — отдельная будущая возможность. [Elgato: Key Logic](https://www.elgato.com/uk/en/explorer/products/stream-deck/key-logic-stream-deck/).

Нужно испытать не только три формы настроек, но и композицию: Switch в single-ветви, длительное действие в hold-ветви, новое нажатие после возврата. Неизмеренные вопросы: пороги жестов, когда становится допустим single, пересечение double/hold, отмена при отключении и смене страницы. Правила нельзя вывести только из названий вкладок.

## Крутилка и её участок полосы — одно действие Encoder

В SDK вращение, нажатие и касание участка полосы относятся к Encoder context. Вращение несёт знаковые ticks и признак pressed; описание триггеров помогает показывать назначение rotate/push/touch/longTouch. Это существенно богаче модели «колесо плюс отдельная произвольная кнопка над ним». [Elgato SDK: Dials](https://docs.elgato.com/streamdeck/sdk/guides/dials/).

Плагин получает `dialDown`, `dialUp`, `dialRotate`, `touchTap`. У `touchTap` есть `hold` и `tapPos`; координаты Encoder находятся в строке 0. В этом API нет общего потока touchDown/move/up или отдельного raw swipe события для action-плагина. Наличие raw touch в драйвере не означает, что его следует напрямую рассылать Elgato-плагинам. [SDK: события](https://docs.elgato.com/streamdeck/sdk/references/websocket/plugin/).

Обратная связь строится из feedback layout: встроенного или JSON layout плагина, обновляемого `setFeedback`/`setFeedbackLayout`. Логическая область одного Encoder на SD+/SD+ XL — 200×100; плагин не рисует произвольно через всю полосу. Преобразование к разрешению N4 требует проверки геометрии. [SDK: layouts](https://docs.elgato.com/streamdeck/sdk/references/layouts/).

## Что делает сенсорная полоса

На SD+ полоса 800×100. Tap и long touch могут быть разными функциями текущего действия; свайп влево/вправо переключает страницы, когда их хотя бы две. Кроме содержимого action есть оформление области крутилки и общий фон. Следует различать фон, feedback действия и навигационный жест. [Elgato: Touch Strip](https://help.elgato.com/hc/en-us/articles/10567698991629-Elgato-Stream-Deck-Touch-Strip).

Отсюда следует проверка: свайп страницы не должен одновременно запускать обычный tap на пройденном участке. Это критерий предсказуемого поведения DeckWeave; точная классификация жеста в текущем Elgato здесь ещё не измерена. Encoder-модель описывает совместимый путь Elgato, но не ограничивает самостоятельную сенсорную панель DeckWeave.

## Уточнение: собственные layouts и самостоятельная панель

Повторно проверены публичные документы SDK 3.0.0: custom layout задаёт собственные элементы и их расположение внутри области action. Поэтому «одна область на крутилку» не означает «одна кнопка/одно число на область». При этом SDK прямо ограничивает canvas отдельной областью; прямое управление всей полосой одним action через этот API не подтверждено. [Custom layouts](https://docs.elgato.com/streamdeck/sdk/guides/dials/), [границы canvas](https://docs.elgato.com/streamdeck/sdk/references/layouts/).

Координаты touchTap позволяют плагину различать места касания своего layout. Это вывод о возможности реализации нескольких функций внутри области; наличие нескольких нарисованных элементов само по себе не доказывает, что host назначает каждому самостоятельное действие другого плагина. Такую композицию нужно проверять отдельно. Внешне цельная панель также не доказывает единого fullscreen context: это могут быть согласованные области одного плагина. Конкретный увиденный владельцем плагин и его редактор пока не идентифицированы.

**Принятое требование DeckWeave после уточнения владельца:**

- Сенсорная панель — самостоятельная поверхность. Плагин панели может задавать виджеты, расположение и интерактивные зоны; число элементов не обязано совпадать с числом крутилок.
- Нужен и знакомый вариант разделения на области по крутилкам, и собственная раскладка панели.
- В подготовленные области помещаются совместимые действия плагинов. Для Elgato необходимо сохранять исходные Keypad/Encoder semantics; нельзя выдавать Keypad-плагин за Encoder только ради картинки.
- Крутилка может управлять связанным элементом панели. Например громкость меняется вращением и отображается на панели; обновление внешней программы также должно быть видно.
- Наличие самостоятельного плагина панели не отменяет совместного использования с крутилками. Конфликты касаний, навигационных жестов и временных индикаторов должен разрешать runtime по описанным правилам.
- Вид в редакторе, аппаратное изображение и области обработки касаний должны соответствовать друг другу. Произвольная геометрия внутри панели не требует бесконечного canvas для расстановки самих устройств.

Это продуктовые требования, а не обещание, что существующий Elgato layout API уже предоставляет готовую вложенность разных плагинов или fullscreen canvas. Контракт собственных панелей и размещение совместимых action instances нужно оформить в будущем дизайне; их нельзя отложить только ради упрощения первой версии.

## Dial Stack и Action Wheel — оба обязательны

**Dial Stack** объединяет несколько действий крутилки. Нажатие выбирает следующее; вращение управляет выбранным. Дополнительная функция, занимавшая нажатие одиночной крутилки, переносится на tap участка полосы. Стек применим к свету, зуму и другим Encoder actions, а не только аудио. [Elgato: Dial Stack](https://www.elgato.com/us/en/explorer/products/stream-deck/what-is-a-dial-stack-for-stream-deck/).

**Action Wheel** размещает клавишные действия в управляемом крутилкой колесе. Вращение и касания по сторонам выбирают действие; нажатие крутилки или касание выбранного действия выполняют его. В редакторе это отдельное назначение из Dials с собственным редактором. [Elgato: Action Wheel](https://www.elgato.com/eu/fi/explorer/products/stream-deck/what-is-an-action-wheel-for-stream-deck/), [настройка](https://help.elgato.com/hc/en-us/articles/28742375481997-Elgato-Stream-Deck-Action-Wheel).

Выбор в колесе и смена действия в стеке — разные операции. Не следует реализовывать оба как один список, где вращение немедленно запускает произвольную команду. Новое решение владельца внесено в [DECISIONS](../../DECISIONS.md); дальнейшие экспериментальные вопросы перечислены в [RESEARCH-GAPS](RESEARCH-GAPS.md).
